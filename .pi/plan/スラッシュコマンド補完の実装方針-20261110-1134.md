## 調査結果
- 現在の `apps/desktop/src/mainview/Composer.tsx` は `/` の候補表示を持たない。一方、SDK のセッションには登録済み拡張コマンド、ロード済みスキル、プロンプトテンプレートがあり、既存の `session.prompt()` は拡張コマンドの処理とスキル／テンプレートの展開を担う。既存テストにも展開の確認がある。
- [pi-app](https://github.com/justhil/pi-app) の調査時 HEAD `703a170` では、セッション由来のコマンドと静的カタログを統合し、名前・説明で絞り込み、カテゴリ付き候補を表示する。↑↓、Enter／Tab、Esc と拡張の引数補完を備え、組み込みコマンドは別途アプリ側で実行している。
- PI-Desktop は提示画像の Skills 一覧とインストール済みバンドルを確認したが、UI の元ソースは直接確認できていない。画像のカテゴリ・説明・操作ヒントを参考にし、内部仕様の一致は主張しない。

## 実装
1. `apps/desktop/src/shared/rpc-schema.ts`、`apps/desktop/src/bun/session-host.ts`、`apps/desktop/src/bun/pi-service.ts`、`apps/desktop/src/bun/index.ts` に、セッションアドレス付きの候補一覧・引数候補 RPC を追加する。現在の `extensionRunner.getRegisteredCommands()` と `resourceLoader.getSkills()/getPrompts()` を正とし、実際の呼び出し名・説明・カテゴリを返す。無効化済み・衝突時の候補は SDK の解決規則に合わせ、存在しないコマンドを推測して表示しない。引数補完は登録コマンドの `getArgumentCompletions` を使用し、エラーは UI に扱える形で返す。
2. セッション切り替え・epoch 変更・リロード時の古い応答を破棄し、候補を開く際に最新情報を取得する。未信頼ワークスペースの既存リソース制限を維持し、候補取得だけのために拡張を別途実行しない。
3. `apps/desktop/src/mainview/Composer.tsx` と新規の候補コンポーネント／CSS・補完ロジックで、入力欄上部にスキル、プロンプト、拡張コマンドを分類表示する。`/` および入力中の接頭辞で絞り込み、説明を表示。カーソル位置を基準に補完対象を特定し、前後のテキスト・既存ドラフト・添付を保持する。↑↓で選択、Enter／Tab・クリックで入力へ補完、Esc でテキストを消さず閉じる。IME 変換中は操作を奪わず、選択中の項目をスクロール表示し、アクセシビリティ属性とローカライズを追加する。拡張が提供する引数候補も同様に表示する。
4. 選択自体では実行せず、補完したテキストを既存のドラフト同期・送信レシート経路から送信する。SDK が拡張コマンド／スキル／テンプレートを処理するため二重実行・二重展開を避ける。モデル不要の拡張コマンドは UI の送信ガードもバックエンドと整合させる。モデルが必要なスキル等は従来通り制限する。未登録の `/...` は既存 SDK の挙動を維持する。
5. pi-app の独自組み込みコマンドを無条件に移植しない。既存アプリに対応する操作と安全な送信・状態遷移があるものだけを候補化し、動作しない項目は表示しない。PI-Desktop 独自の `/skill:imported...` 形式を盲目的に複製せず、この SDK が実際に受理する名前を使う。

## 検証
- バックエンドテスト：拡張登録コマンド（ponytail 相当の fixture を含む）、スキル、テンプレート、名前衝突、引数候補、リロード・セッション切替・未信頼状態を確認。送信が一度だけ実行されることと、モデル不要コマンド／モデル必要な入力の挙動を検証。
- フロントエンドテスト：検索、カーソル位置・選択範囲、↑↓／Enter／Tab／Esc、クリック、IME、既存テキスト・添付の保持、古い非同期応答の破棄を確認。
- `mise exec -- pnpm typecheck`、`mise exec -- pnpm lint`、関連テストを実行し、可能ならデスクトップ UI で `/` から ponytail コマンドが候補に出て実行されることを確認する。実機環境の制約があれば明記する。
