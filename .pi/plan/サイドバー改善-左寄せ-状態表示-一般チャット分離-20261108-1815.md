## 目的
チャットタイトルを左寄せにし、「実行中」「完了・未読」「入力待ち」を判別可能にする。プロジェクトに属さない一般チャットを、プロジェクト配下のチャットと分離する。

## 調査結果
### 現在の実装
- `apps/desktop/src/mainview/SessionList.tsx`：チャット操作・ピン・アーカイブは実装済み。実行中判定は削除禁止に使用しているが、行には表示していない。
- `mainview/styles.css`：共通ボタンが中央寄せ。`.thread-row .thread` に左寄せの指定がない。行単位で修正すれば他のボタンに影響しない。
- `mainview/App.tsx` / `mainview/rpc.ts`：プロジェクト一覧のみ描画・取得。一般チャットの作成経路がない。
- `bun/index.ts`：セッション操作は登録プロジェクトの cwd に限定。リンク解決もプロジェクトのみ検索している。
- `bun/notifications.ts`：`agent_settled` を使い、成功・失敗・中断を区別する既存トラッカーがある。これを再利用する。
- `mainview/store.ts`：通知履歴の既読はあるが、会話の既読状態はない。通知の削除・既読操作を会話の既読と同一視しない。
- `bun/extension-ui.ts`：select / confirm / input / editor は即キャンセルされる。質問待ちアイコンだけ追加しても実際には待てない。
- インストール済み pi SDK の型・RPC 文書で、標準 UI の戻り値、要求 ID と応答の対応、AbortSignal / timeout を確認した。

### 先行クライアントから採用する設計
1. [vastsa/PI-Desktop：状態判定](https://github.com/vastsa/PI-Desktop/blob/main/apps/desktop/src/lib/sidebar-session-status.ts)
   - permission → running → selected → outcome のように優先順位を一か所で決定する。
   - 本実装も純粋な判定関数にまとめる。ただし「完了」と「未読」は別に管理する。
2. [vastsa/PI-Desktop：所属の分類](https://github.com/vastsa/PI-Desktop/blob/main/apps/desktop/src/lib/sidebar-session-groups.ts)
   - プロジェクト所属なしを独立したセクションとして扱う。
   - 本アプリの pi セッションは cwd 必須なので、nullable 化を全体に広げず専用 cwd で対応する。
3. [gustavonline/pi-desktop：サイドバー](https://github.com/gustavonline/pi-desktop/blob/main/src/components/sidebar.ts)
   - 実行中と attention を別管理し、プロジェクトに attention 件数を集約している。
   - その考え方のみ採用し、並べ替え・ワークスペース・ファイルツリー等は持ち込まない。

## 採用する UI
```text
pig                         通知

チャット                      ＋
  ◌ 調べものについて
  ✓ 完了した相談

プロジェクト                  ＋
  ▾ 📁 pig              ●1
    ◌ サイドバー改善
    ✓ チャット UI 改善
    ● 確認が必要な作業
```
- 全タイトルを左寄せ・一行省略。状態欄は固定幅にして文字の開始位置を揃える。
- 選択状態は行背景。状態アイコンと独立させる。
- 入力待ち：オレンジの点。開いただけでは消えず、回答・キャンセルで解除。
- 実行中：回転するリング。reduced-motion では静止表示。
- 正常完了・未読：緑のチェック。会話を表示して既読にすると消える。
- 失敗・未読：赤い警告。成功チェックと区別する。中断は正常完了扱いにしない。
- 既読・待機中：原則アイコンなし。選択中の待機行は必要に応じて輪郭の丸を使用。
- 優先順位は **入力待ち > 実行中 > 未読の結果 > 選択中の待機 > 通常**。
- tooltip とアクセシブルな状態ラベルを付け、色だけに依存しない。
- プロジェクトは折りたためるようにし、折りたたみ中も入力待ち件数と未読の有無を表示する。ピン・アーカイブ・メニューの既存操作は保持。

## 実装手順と対象
パスは `apps/desktop/src/` を基準とする。

### 1. 一般チャットの追加
対象：`bun/desktop-config.ts`、`bun/index.ts`、`shared/rpc-schema.ts`、`mainview/store.ts`、`mainview/rpc.ts`、`mainview/App.tsx`。
- アプリ管理領域に一般チャット用の専用作業ディレクトリを作り、Bootstrap でその cwd を返す。
- プロジェクト一覧とは別に一般チャットを取得する。既存 `SessionList` と作成・再開・改名・削除・ピン・アーカイブを再利用する。
- セッション操作の検証は「登録プロジェクトまたは専用 cwd」のみ許可。任意の cwd を許す変更にはしない。
- コピーリンク、戻る／進む、通知からの遷移、fork が一般チャットでも機能するよう対応する。
- 「チャット」の＋は一般チャット、「プロジェクト」の＋はフォルダ追加、各プロジェクトの＋はその中のチャット作成。
- プロジェクトがゼロでもチャットを開始できるよう空状態を修正。
- 既存履歴の移動・再分類はしない。プロジェクトを一覧から外しても、一般チャットに自動変換しない。

### 2. 実行状態と完了未読
対象：`bun/notifications.ts`、`bun/index.ts`、`bun/desktop-state.ts`、`shared/desktop-state.ts`、`shared/rpc-schema.ts`、`mainview/store.ts`、`mainview/rpc.ts`。小さな状態判定モジュールとテストを追加。
- 既存 completion tracker を完了判定の唯一の根拠として使い、通知文やツール名から推測しない。
- 完了結果とその識別子、既読済み識別子を既存 desktop state に保持。再起動しても未読を維持する。既存データで値がない場合は既読扱い。
- 表示中の会話かつウィンドウが可視・フォーカス中なら既読化。別会話・設定画面・バックグラウンド中の完了は未読のまま。
- 既読 RPC は対象の完了識別子を指定し、直後に届いた新しい完了を誤って消さない。
- 通知センターの「全て既読」「履歴削除」と会話の未読を切り離す。
- 実行中・質問待ちは現在のライブ状態。再起動後に古い実行中表示を復元しない。

### 3. 標準の入力待ちを実際に扱う
対象：`bun/extension-ui.ts`、`bun/pi-service.ts`、`bun/index.ts`、`shared/rpc-schema.ts`、`mainview/rpc.ts`、`mainview/store.ts`、`mainview/App.tsx`。小さな回答 UI を追加。
- select / confirm / input / editor を要求 ID・セッション ID 付きの要求／応答に接続する。
- バックエンドを保留要求の正とし、会話を切り替えて戻っても要求を再表示できるよう snapshot 等で同期する。
- 選択中の会話内に回答欄を表示。他会話の質問で画面を強制切替しない。
- 選択肢・戻り値の型・対象セッション・要求 ID を検証。二重回答を防止する。
- 回答、キャンセル、AbortSignal、timeout、セッション終了時に保留要求を必ず解除する。
- `custom()` の独自 TUI は今回対象外。既存の非対応エラーを維持し、待機表示を偽装しない。

### 4. サイドバーの描画と翻訳
対象：`mainview/App.tsx`、`mainview/SessionList.tsx`、`mainview/styles.css`、`shared/i18n.ts`。
- 左寄せ、固定幅状態アイコン、セクション見出し、折りたたみ、プロジェクト集約表示を追加。
- 既存の色トークン・lucide-react・メニュー実装を使用。依存追加はしない。
- 日英のラベル、キーボード操作、aria-expanded / aria-current、長いタイトルの省略を整える。

## 検証
- 状態優先順位、成功／失敗／中断、再実行、非アクティブ会話の完了、既読 ACK と次の完了の競合。
- 完了未読の保存・再読込、既存 desktop state の後方互換、ピン・アーカイブとの共存。
- 標準 UI の要求→回答、キャンセル、timeout、abort、二重回答、不正な要求 ID、会話切替と再同期。
- 一般チャットの作成・再開・一覧・リンク・fork・削除と、任意 cwd の拒否。既存プロジェクト履歴が変更されないこと。
- 実画面で左寄せ、長い日本語タイトル、全状態、折りたたみ集約、キーボード操作を確認。
- コマンドはすべて rtk 経由：`rtk proxy mise exec -- pnpm typecheck`、`rtk proxy mise exec -- pnpm lint`、`rtk proxy mise exec -- pnpm test`。既存の失敗と今回の回帰は分けて報告する。
- 実装開始時に作業チェックリストを作成。委譲が必要な独立タスクに限り `openai-codex/gpt-6.1-sol` を使用する。

## 対象外・注意点
- D&D、検索、並べ替え設定、リサイズ、プロジェクト間移動、独自 TUI の汎用描画は追加しない。
- 一般チャットは「プロジェクト非所属」であり、ツール無効化やファイルアクセスのサンドボックスではない。既存プロジェクトの cwd を暗黙に引き継がせない。
- 調査では既存の未コミット変更が多数あることを確認した。これらを維持し、関連箇所のみ変更する。
- 現時点ではソース調査のみ完了。実装・テスト実行・実画面検証はまだ行っていない。
