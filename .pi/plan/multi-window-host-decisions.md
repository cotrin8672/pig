# マルチウィンドウ基盤：判断待ちメモ

ブランチ `feat/multi-client-host`（8169ba8, 3bdb0e4）。

## 既存実装と衝突・挙動が変わる点

1. **2回目の起動は新しいウィンドウを開く**（既存ウィンドウの前面化ではない）。
   stable と nightly は identifier・channel が同じなのでパイプ名も同じ。stable 起動中に nightly を起動すると stable のウィンドウが増える。dev channel は別パイプなので、従来どおり stable と同時に動く。
2. **下書き競合の表示文言**：別ウィンドウで同じチャットを編集中に競合すると、既存の「An extension changed this editor…」カードが出る（Composer.tsx:400）。文言・i18n の変更は UI 変更なので未着手。
3. **拡張ターミナルの2枚目のウィンドウ**：操作権がないウィンドウでは空のターミナルダイアログが開き、最初の1回だけ「This terminal is open in another window.」のエラー通知が出る。ダイアログ内の状態表示は未実装（UI 変更）。文言は英語のみ。
4. **エラー・ログイン通知は全ウィンドウに配信**：あるウィンドウの操作で起きたエラーのトーストが他のウィンドウにも出る。ログインの進行フレームは、他ウィンドウでは無視され、成功時の再読込だけが走る（既存の受信側の挙動）。
5. **送信中の復元**：あるウィンドウで送信が受付待ちのときに別ウィンドウを開くと、そのウィンドウにも送信中として表示される（既存の `sends.restore`）。
6. **新しいウィンドウを開く UI がない**：開けるのは再起動時だけ。メニュー・ショートカットは未実装。

## 計画からの変更

- ホストAPIを `host-api.ts` に切り出さず、`app.ts` 内の `hostRequests` / `hostMessages`（ウィンドウ非依存）とウィンドウ依存のハンドラに分けるだけにした。依存の注入を書き直す規模に見合わないため。
- `clientId` を `sessionStorage` に保存する案は不要だった。ページ再読込時は `will-navigate` で、そのウィンドウのリースだけを解放する。
- `UIConnectionLease` は変更していない。1クライアントだけ切れても他を止めない挙動は既存のままで十分だった。
