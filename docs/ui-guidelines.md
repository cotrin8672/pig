# UI共通ルール

UIの追加・変更・レビュー時に適用する。スクリーンショットごとの場当たり的な修正ではなく、
同じ役割のUIに同じ基準を適用するための規約。
新しい共通の指摘・合意は、実装と同時にここへ追記する。

## 自動検査（文書だけに依存しない）

| 検査 | 自動で止めるもの |
| --- | --- |
| `pnpm lint` → `lint:ui` | Cardへの不透明な背景・全体opacity、許可トークン自体の不透明化、inline styleでの背景指定、個別のスクロールバー形状・native thin/color指定、native Tooltip用の `title` 属性 |
| `pnpm test:ui` | 実描画でのスクロールバーの端の非対称・見切れ、Cardの背景alphaと全体opacity、出力枠の左右の不整列、8行上限、サイドバーアイコン列の上下余白、ターミナル枠内の最低1pxの隙間 |
| CI / Release | 毎回は静的Lint・軽量テスト・Webビルド。重い実描画は毎日／手動の `Regression` に分離 |

- 静的検査は `apps/desktop/scripts/ui-style-rules.ts`。CSS・セレクター・JSXをASTで解析する。
  `check-ui-styles.ts` が本番の `mainview` 配下を走査し、違反箇所をファイル・行番号付きで出力する。
- 新しい通常Cardは `*-card` / `ui-card` クラス、または `data-ui-surface="card"` を使う。
  `session-panel` と `response-error` もCardとして検査する。任意の名前から役割を推測する検査ではない。
- 背景は許可された半透明トークンを共有CSSから指定する。Cardのinline styleはレイアウト用途に限る。
  動的なstyleオブジェクトやspreadで検査を迂回しない。
- UI変更時は、通常CIの成否とは別に `pnpm test:ui` を実行する。`Regression` のUIジョブも
  同じ検査を実行し、ブラウザ不在はスキップせず失敗する。検査頻度の分離であって削除ではない。
- 描画検査は `transcript-ui.test.ts`。スクリーンショットのthumbのピクセルと実要素の寸法を測る。
  スクリーンショット全体の一致だけで判定する方式ではない。
- 新しいCard・スクロールUIは描画fixtureにも追加する。検査対象を外す・スキップする・
  許容誤差を広げることを、不具合修正の代わりにしない。
- すべての美的判断を自動判定できるわけではない。新しい指摘のうち数値化・ルール化できるものは、
  文書だけで済ませずLintの違反例テストか描画の回帰テストへ追加する。

## 1. 既存の見た目と共通実装を使う

- 色・文字・角丸は `apps/desktop/src/mainview/tokens.css` のトークンを使う。
  似た色や角丸を個別にハードコードして別体系を作らない。
- 同じ役割の枠・操作・スクロールには、既存コンポーネントと共通CSSを使う。
- `ContentPage` の戻るボタン・見出しの位置は画面間で揃える。見出し横の操作は共通の `actions` に渡し、
  画面側でヘッダーを `display: contents` にして再配置しない。本文を全幅にする画面でもヘッダーの共通幅を保つ。
- テキスト入力の共通CSS（幅100%・padding・flex）はcheckbox / radioへ適用しない。
  選択一覧では、チェック欄が本文を枠外へ押し出していないことも描画で検査する。
  型の除外条件には `:where()` を使って共通ルールの詳細度を低く保ち、
  検索欄等の既存コンポーネントによる背景・枠の打ち消しを妨げない。
- グラフのカテゴリ色は、状態色・通知の差し色と別の、見分けやすいパステル系の配色を使える。
  同じグラフとその凡例は配色を共有し、色を変えるために配置・寸法を変えない。
- 統計は設定・Providerと同じ `ContentPage` を使い、本文は共通の余白を保って利用可能な幅・高さを使う。
  期間タブは見出しと同じ行に置き、記録開始日は常設表示しない。並べた円グラフは凡例の行数が違っても
  直径・上下位置を揃える。`statistics-ui.test.ts` で通常幅・狭い幅・リサイズ時の実描画を検査する。
  ツールCardは「ツール／初期コンテキスト」を同じCard内で切り替え、内容によらず高さを変えない
  （切り替えで円グラフを動かさない）。初期コンテキストの内訳はシステムプロンプトのセクション別と、
  ツール定義の提供元（拡張）別に示し、提供元の行を開くと個々のツールを表示する。
- 同種の問題を見つけたら、会話、ツール出力、サイドバー、設定、通知、Picker、
  ダイアログ、セッションパネルも横断して確認する。
- 既存実装の逸脱は、新規UIでも逸脱してよい根拠にはしない。
  共通ルールから外れる新しいデザインは、先にユーザーに確認する。
- 拡張ツールのCompare Storyは、比較候補の前にツールの用途・入力・出力を説明する。
  表示案の意図だけでなく、ツールを知らなくてもサンプルの意味を判断できるようにする。

### ツールチップ

- 未スタイリングのホバーテキストは表示しない。native `title` は削除し、必要な操作名・補足は
  `aria-label` / `aria-description` に残す。共通Tooltipを使っている箇所は維持し、
  削除の代わりに全ボタンへTooltipを新設しない。DOM要素と `ConfirmButton` の `title` 属性はLintで禁止する
  （`ContentPage` 等の見出し用 `title` propは別）。
- サイドバーの「新しいチャット」ボタン（プロジェクト内も含む）にTooltipは付けず、アクセシブル名は残す。
- ホバーの補足はnative `title` ではなく共通Tooltipを使う。面は `mainview/tooltip.css` の
  `ui-tooltip`：`--ds-bg-popover` にアクセント色4%を混ぜ、さらに明るい中性色
  `--ds-text-primary` を12%混ぜた面を50%に固定する。テーマ色を減らした分の暗さを白みで補う。
  `blur(4px) saturate(140%)`、アクセント16%の1px枠、`--ds-shadow-dialog`。
  通常のTooltip・使用量の詳細・統計グラフのホバー表示で同じ面を使う。強調する見出しは `ui-tooltip-title`。
- Tooltipは文字の上に小さく重なるため、Popoverの `blur(var(--ds-popover-blur))` を使わない（細かい文字が均一な色に溶けて
  不透明に見える）。アクセント色を混ぜるとalphaが上がるので、`rgb(from … / 0.5)` で戻す。
- 中身の型（1行／キーキャップ付き／見出し＋説明／見出し＋値の一覧）とキーキャップの有無は用途で選ぶ。
  見た目の例はStorybookの `Components/Tooltip`。
- Storybookで色を比較するときはTooltipだけでなくウィンドウ全体に同じテーマを適用し、
  壁紙も同じ基準に揃える。半透明の合成色は背景で変わるため、seedの一致を見た目の一致と扱わない。
  `tooltip-theme-ui.test.ts` でシェル・壁紙・Tooltipのテーマ一致を検査する。
- 実装は `mainview/Tooltip.tsx`：アプリに1つの `TooltipLayer` と、アンカーに展開する `useTooltip()`。
  アンカーには `data-tooltip-anchor` が付き、文字の上でもIビームではなく矢印カーソルになる
  （`:where()` で詳細度0。ボタン等の `pointer` は維持）。
  個別に表示処理を書かない。チャット名など長い文字は `clipTooltipText` で上限（80字）に切る。
- 例外として、見切れたシェルコマンドの見出し（`.tool-cmd`）は、見切れているか複数行のときだけ
  全文を `code`（等幅・折り返し・8行まで、幅420px）で出し、下に状態・実行時間・シェル・タイムアウト・出力行数を
  値の一覧で添える（`ToolBlock.tsx` の `shellTip`、Storybookの `Components/Tooltip`）。
- 出現アニメーション（`tooltip-in`、`data-side` 方向へ3pxのフェード）は `ui-tooltip` 側に持たせ、
  独自の面（使用量の詳細など）も同じ動きにする。行の移動で中身を差し替えるときは再生しない。
  描画テストは `tooltip-in` を `finish()` してから画素を測る。
- 隙間のない行（セッション一覧など）を移るときは同じTooltipを開いたまま、新しい行へ140msで滑らせ、
  中身だけをクロスフェード（`tooltip-swap`）する。中身と位置を瞬時に差し替えるだけにしない。
  隙間を挙んだ移動（アイコン列）は一度閉じ、従来どおり `tooltip-in` で出現させる。
  使用量の詳細Popoverも同じ共通クラス（`ui-tooltip-follow`・`ui-tooltip-swap`）で揃え、中身は行ごとにkeyを変えて
  データ更新では再生しない。キーボード操作でのスクロール追従は滑らせず即座に合わせる。
  統計画面の棒グラフ・円グラフのTooltipも共通の `useFollowTip`（`follow-tip.ts`）と `ui-tooltip` の面で同じ動きにする。
  円グラフはスライスと凡例の行のどちらにホバーしても、そのスライスを強調して他を薄くし、スライスの中点に出す。
  `tooltip-ui.test.ts`・`provider-usage-hover-ui.test.ts`・`statistics-ui.test.ts` で検査し、比較用の代替案はStorybookの `Components/Tooltip` に残す。

### 情報量の多いホバー表示

- 複数の値・日時を含む補足は、文字列だけのnative tooltipではなく、共通Tooltipの面（`ui-tooltip`）で
  見出し・数値・補足を整理する。
- 一覧では文字だけでなく、アイコン・数値・行の余白を含む行全体をホバー範囲にする。
  Popoverの表示で行や周囲の配置を変えない。
- キーボードfocusでも同じ情報を表示し、Escapeで閉じる。Popoverへポインターを移す途中で
  閉じず、サイドバーのoverflowで欠けないようtop layerを使う。
- Popoverは一覧ごとに1つだけ持ち、行の移動では中身と位置を差し替える。行ごとにPopoverを
  持って閉じる遅延の間に重ねない。クリックによるfocusで開いたままにせず（`:focus-visible`
  のときだけfocusで開く）、ポインター起点のものは一覧のスクロール・リサイズで閉じる
  （`ActionsMenu` と同じ）。面は共通Tooltip（`ui-tooltip`）。`provider-usage-hover-ui.test.ts` が実入力で検査する。
- 背景系の面（shell・サイドバー・Popover・Composer・elevated等）は、背景透過時と同じごく薄い
  テーマ色に揃える。primaryと同じ色相・chroma 8上限の共通パレット（`surfaceChroma`）を使い、
  ただし浮くガラス（`--ds-bg-popover`：Composer・Popover・通知パネル）は、暗い灰色に色相を少し足すのではなく
  shellの面にアクセント色を12%だけ混ぜ、不透明度50%にする。テーマ色が「ほんのり分かる」薄い色にし、
  背景が透けて見えることを優先する。ぼかしは共通の `--ds-popover-blur`（8px）。
  Composerは会話を見ることが大事なのでblurを付けない（`composer-layers-ui.test.ts` で検査）。
  Acrylicでも彩度や明度を持ち上げない（無彩色seedはneutral）。文字色はneutralのまま。
  広い面や重ねたCardでテーマ色を主張させず、アクセントは操作・フォーカス・小さな印に残す。
- 差し色 `--ds-highlight`（面は `--ds-bg-highlight`、上の文字は `--ds-on-highlight`）はtertiaryパレットから作る。
  「ここを見て」を示す小さな印だけに使う：未読（サイドバーの未読点・通知バッジ・未読点）、
  ユーザーの操作待ち（拡張の入力要求ダイアログの枠・待機中リクエストの選択）、
  検索（一致箇所・`search-target`の輪郭・`mark`）、アプリ・インストール済み拡張機能の更新の検出
  （設定・拡張機能アイコンの `sidebar-update-dot`。更新Badgeは右上、Providerの状態点は右下。
  大きさ・右端の余白は共通）。Card等の広い面、本文・リンク、成功／警告／失敗の意味には使わない。
  通常の選択・ボタン・フォーカスは従来どおり `--ds-accent`／`--ds-focus`。
  チャット・プロジェクトの状態点（`session-dot`）は状態の意味色なので差し色にしない。
  Popover背景は60%の色レイヤーとする。ウィンドウ背景の上へ80%の面を重ねると、
  合成後はほぼ不透明になり背景色を失う。60%を超えて濃くせず、個別の色や全体opacityで
  読みやすさを補修しない。
  同テストで共通Tooltipとの描画像の色一致・縞模様のぼかし・ウィンドウ背景越しの壁紙色の透過を検査する。

### キーボードフォーカス

- ブラウザ標準の白黒のフォーカス枠を出さない。`:focus-visible` は全要素で共通のテーマ色の枠
  （`--ds-focus`＝`--ds-accent` と同じトーンを70%、2px、`outline-offset: 2px`）にする。
  スクロール領域は枠が切れないよう内側（`-2px`）に描く。角丸の親に接する領域は、枠にも親と同じ角丸を付けて
  角で見切れさせない（会話領域は `.main-clip` と同じ `--radius-sm`。`pane-updates-ui.test.ts` で検査）。
- 検索・注釈で移動するだけの要素（`.response-turn`・`[data-content-index]`・`.annotation-card`）は
  操作部品ではないので枠を出さない。位置は `search-target` で示す。

### 動的配色とカラーピッカー

- 設定に保存するのは不透明なsRGBのseed色だけ。Material Color UtilitiesのTonalSpotから
  `dynamic-theme.ts` で共通 `--ds-*` トークンへ変換し、画面ごとに配色計算を追加しない。
  無彩色seedの背景・アクセントはMonochromeにする。形・文字・余白のトークンは変更しない。
- 失敗色はMaterialのError、成功・警告は緑／アンバーの追加TonalPaletteをseedへharmonizeする。
  Primary上の文字には専用の `--ds-on-accent` を使い、背景色で代用しない。
- 動的配色でもCardのalphaを維持する。任意の壁紙・透明度でコントラストを保証できると扱わず、
  seedの極端値・不透明度・背景効果ごとに実描画を確認する。
- コードの構文色はCSS変数で既存DOMに反映し、色変更だけで再解析・再マウントしない。
  ANSIの色番号・明示RGBはテーマに合わせて置換しない。
- カラーピッカーは共通 `ColorPicker` を使う。Popoverは半透明背景・blur・共通角丸／影を再利用し、
  top layerでCardのクリップを避ける。色面・色相・HEX・プリセットを備え、キーボード操作とEscapeを保つ。
  色面の白／黒・色相スペクトル・色見本は編集対象そのものなのでUI配色トークン化の対象外。
- `dynamic-theme.test.ts` で色生成・コントラスト・Cardのalphaを、`dynamic-theme-ui.test.ts` で
  実際の設定・ピッカー操作・透過・配置不変・構文DOMの保持・ANSI不変を検査する。

## 2. Cardの背景は半透明のレイヤー

通常のCardは、ウィンドウの背景・透過感を引き継ぐ薄い重ね塗りにする。
不透明な色の板を置いて、背景から切り離さない。

| 用途 | 基準 |
| --- | --- |
| 設定・一覧・情報Card | `--ds-tile`、必要に応じて `--ds-elevation-stroke` |
| 控えめなツール・状態の枠 | `--ds-tool-row-bg` |
| Cardのhover | `--ds-tile-hover` など既存の状態トークン |
| 浮いているメニュー・Popover | `--ds-bg-popover` と既存のぼかし・影 |
| 会話の上に開く検索パレット・入力要求／信頼ダイアログ（`SolidBlurFilter`） | `--ds-bg-elevated-opaque` 64%＋`blur(24px) saturate(140%)`＋不透明化フィルタ（下記） |
| コード・ターミナル | 共通CSSの半透明背景レイヤーを再利用 |

- 背景色のalphaで透過させる。Card全体に `opacity` を付けて文字やアイコンまで薄くしない。
- ウィンドウが透過しているため、`backdrop-filter: blur()` の結果自体も半透明になり、背後の鮮明な文字が
  blurを通して透けて見える（通常のEdgeでは再現しない）。文字の上に大きく重なる面は、検索パレットのように
  `feFuncA` でalphaを引き上げるSVGフィルタを `blur()` の後ろに続け、ぼかしを不透明にする。
  `::backdrop` にblurを足して代用しない（面の外側までぼける）。
- 枠を持つ入力行（検索パレット・パッケージ検索など）の中の `input` は、グローバルの入力枠・背景を
  打ち消して内側に二重の箱を描かない。
- 検索パレットは入力行を画面上部（通常20vh）へ置き、候補数で位置を動かさない。
  長い会話全体をinert化するnative modalは開く際に重いため、既存の非モーダルdialog方式を使い、
  外側クリック用の背景レイヤー・Escapeで閉じる処理・元の入力へのフォーカス復帰を維持する。
- シェルのミニターミナル（`.tool-term`）は、状態色（実行中・成功・失敗）を約7%混ぜた半透明の面と
  同系色の1pxリングで状態を示し、ログはその内側の一段暗い半透明層に置く。状態表示は右上の
  小さな点と所要時間（失敗時は終了コード）。実行中は点がゆっくり脈動し、ログ末尾の四角い
  キャレットがゆっくり点滅する。どちらも `prefers-reduced-motion` では止める。
  出力更新や一時IDから保存済みIDへの切り替えで状態点・キャレットを再マウントせず、
  アニメーションの位相と経過時間を維持する。Reactのキーは `liveToEntry` の対応を使って維持し、
  検索・操作用のrecord IDは保存済みIDへ更新する。
  `transcript-ui.test.ts` でbash／PowerShellの連続更新・保存時のDOM・開始時刻・経過時間を検査する。
- Popoverを含む要素自身に `backdrop-filter` を付けない。その要素がbackdrop rootになり、内側のPopover（モデル
  Picker・スラッシュ候補）はその外側の会話をぼかせず、背景がそのまま透ける。Composerのように、すりガラスは
  `::before` などの層へ移し、親は `isolation: isolate` で重なりを闉じる。`filter`・`opacity`・`mask`・
  `clip-path`・`mix-blend-mode` も同じ境界になる。`composer-layers-ui.test.ts` が実描画の画素で検査する。
- 要素内に絶対配置で開くPopover（通知パネル等）には `z-index` を付け、使用量バーの枠など
  `z-index` 付きの周囲の部品に上書きさせない。`notification-center-ui.test.ts` で検査する。
- 通常のCardに `--ds-bg-elevated-opaque` や不透明な `--ds-bg-secondary` を流用しない。
- `background: transparent` だけで枠の区別を失わせることも、半透明Cardの代用にはしない。
- 背景レイヤーを無目的に入れ子にして、不透明に近づけない。
- 既存のモーダル・ネイティブ選択UI・対話型ターミナルなど、可読性のために不透明な面を
  使っている専用UIは別扱い。通常のCardへその例外を広げない。
- Acrylic / Mica / 透明背景やウィンドウの不透明度設定を変えても、
  背景との一体感と文字の可読性を両立させる。

### Windowsのカスタムタイトルバー

- `WS_CAPTION`・リサイズ・Snap用の標準ウィンドウ属性は維持し、タイトルバーの表示領域だけを
  Electrobunの `hiddenInset` に任せる。属性の削除でタイトルバーを隠さない。
  最大化時にタスクバーを隠したり、自動非表示のタスクバーを呼び出せなくなるため。
- DWMのフレーム拡張は外周1pxに留める。全面glass（margin `-1`）は自動表示の帯の下にも
  標準の最小化・最大化・閉じるボタンを描いてしまう。帯のボタンだけを表示し、透過は既存の
  空のblur regionで維持する。`windows-smoke` の透過検査は、帯が閉じた右上の実画素にも
  余分なボタンがないことを検査する。
- 最大化・復元・アクティブ切替で標準タイトルバーが再表示されないこと、最大化が作業領域を
  はみ出さないことを検証する。自動非表示時は画面端の実カーソル入力でも確認する。
  `scripts/windows-smoke.ts --interactive` のネイティブ検査を使い、Windowsの設定自体は変更しない。

## 3. 余白・枠・アイコンの整列

- 同じ階層の枠は左右端を揃える。枠ごとに幅やインデントを変えない。
- ターミナルの内側には最低1pxの余白を設け、スクロール領域を外枠のリングに密着させない。
- ターミナルの外枠は、ファイル表示・書き込み・編集差分の本文枠と同じ左右端にする。
  現在の共通本文インデントは22px。見出しのアイコン位置とは区別する。
- アイコンだけの操作は、当たり判定の中央に配置する。状態表示用の空枠を残さず、左右・上下のpaddingを対称にする。
- アイコン列は、ボタンの当たり判定を含めた領域の上下に同程度の余白を取る。
  サイドバー下部は上12px・下12pxが基準。
- 応答フッターのホバー操作はモデル情報と同じ行に置き、非表示の操作専用行で空白を作らない。
  モデル切り替えの区切り線の上は直前のメッセージ・フッターの余白を使い、余白を重ねない。
- Providerアイコンを添えたモデル表示では、Provider名や `provider/` の接頭辞を本文へ重複表示しない。
  会話内のモデル切り替え区切りもアイコン＋モデル名だけにし、完全な `provider/model` はアクセシブルな説明に残す。
- 空きができる片側だけにpaddingを足す、負のmarginでその場だけ揃える、といった補修をしない。
- 角丸のある親子では、子の背景・枠・スクロールバーを親のカーブに食い込ませない。
- 幅が狭いとき、長いファイル名やコマンドでも整列を崩さない。
  省略表示・折り返し・枠内スクロールを役割に応じて使う。

### Pane

- PaneはCard化せず、共有背景を1pxのDividerで区切る。境界はドラッグ・矢印キーで調整する。
- 各Pane上部に小さなwinbarを置き、Project名とセッションタイトルだけを1行で表示する。
  背景は完全透明、枠線・Card・操作ボタンは足さない。文字サイズと行高は共通トークンを使い、
  長い名前は省略して横にはみ出させない。未送信のPaneでも同じ高さで表示し、
  非アクティブPaneのタイトル変更も反映する。本文更新だけではwinbarを再描画しない。
- 非アクティブPaneのComposerは一体で沈め、アクティブPaneを浮いたComposerで示す。面は透明にせず `--ds-tile`＋
  `--ds-border-default` の枠、影なし。文字・アイコンはModelPicker等も含めて全て同じ薄さ
  （faintを50%透過）に揃え、一部だけ通常色で残さない。Disableにはせず、クリックでそのまま入力できる。
  大きさ・位置は変えず、全体の `opacity` も使わない。`inactive-pane-composer-ui.test.ts` で検査する。
  縦（左右）・横（上下）の分割ボタンは展開するウィンドウタイトルバーに並べ、最小化ボタンの左に12pxの間隔を取る。
  閉じるボタンはZenバーでなく各Paneの右上に本文と重ねて配置し、そのPaneだけを閉じる。
  Zenバーとその起動範囲に隠れない位置に置き、閉じる操作の専用領域は予約しない。
  「新しいチャット」は閉じるボタンの左に同じ寸法・縦位置で並べ、Paneが1枚でも表示する。
  操作したPaneのプロジェクトで開き、元のセッション・実行・下書きは保持する。他Paneの内容は変えない。
  非アクティブPaneを閉じても他Paneのフォーカス・入力を奪わない。Paneが1枚のときは閉じるボタン自体を描画しない。
  セッションの削除・停止やウィンドウ全体の閉鎖と区別する。
  ウィンドウ操作と縦位置・アイコンの余白を揃え、ドラッグ対象にしない。チャット以外では同じ位置で無効化する。
  分割・閉鎖は既存のショートカットからも操作できる。
- 分割はフォーカス中のpaneを対象とし、別方向はその中だけを分割する。同方向の追加は兄弟を均等配置する。
- 新規チャット・分割で作るPaneは、SDK起動やセッション作成を待たず共通の空チャット画面とComposerを表示する。
  SDK起動・セッション作成は初回送信時だけ行い、未送信の画面をチャット一覧に追加しない。
  同じプロジェクトでもPaneごとに下書き・モデル選択を分離し、非アクティブ時も空画面と入力を維持する。
- フォーカス移動・分割・サイズ変更で会話と下書きのDOMを保持する。Paneを閉じてもセッションは削除・停止しない。
- 各Paneは自分のSnapshotを購読し、非アクティブでも更新を続ける。他チャットの更新や起動進捗で
  無関係な本文を再描画しない。Appの画面枠はSnapshot全体でなく、タイトル・接続状態・設定など
  必要な値だけを購読し、アクティブ会話の本文更新でも再描画しない。`pane-updates-ui.test.ts` が
  本番Appで枠側の再描画0回、無関係な本文の再読取0回、タイトル更新、IME中の文字・カーソル、
  独立したスクロール位置、フォーカス・分割・リサイズ時のDOM保持、epoch切り替えを検査する。
- 注釈の選択範囲は各Paneの会話領域に限定する。PopoverをbodyへPortalしても選択元を維持し、
  注釈の追加・Composerへのフォーカス復帰で別Paneの下書きを変更しない。`pane-updates-ui.test.ts` で検査する。

### 会話履歴の自動読み込み

- 「以前のメッセージを読み込む」ボタンを置かず、スクロールが先頭付近へ来たら1ページずつ先読みする。
  先読み範囲は約1画面（最低320px）。初期表示で全履歴を一括取得せず、取得済みの履歴は破棄・仮想化しない。
  マウス・タッチだけでなく、フォーカス可能な会話領域のキーボードスクロールでも動作させる。
- 同じ表示のowner・履歴revision・cursorへの要求は1本にまとめる。履歴の先頭到達で止まり、進まないcursorはエラーにする。
  古い分岐・epoch・unmount後の応答で履歴を復活させない。失敗は既存通知に出し、会話内のエラー行や
  ローディング行で本文を動かさない。再接近・focus復帰・online復帰で再試行でき、先頭でも再度の上スクロール等で
  再試行できる。失敗直後の入力連打には短いcooldownを設け、連続要求は避ける。
- 履歴追加時は要求開始時でなく、反映直前に読んでいる要素と表示位置を基準にする。配信中の末尾の成長を
  先頭追加量に混ぜて補正しない。追加後の数式・画像等の遅いレイアウト変化でも読む位置を保つ。
- 追加後のアンカー保持は、次のホイール・タッチ・ポインター・キー操作、検索ジャンプ、末尾への移動で解除する。
  通常スクロールをpreventDefaultしたり、操作後に以前の読む位置へ引き戻したりしない。
- `history-paging-ui.test.ts` が実Edgeのtrusted wheel/keyboard/input、先読み、重複要求防止、選択・下書き・
  既存DOM・読む位置、遅い数式整形、操作後のアプリ側scrollTop書込0回、失敗回復、古い応答の破棄を検査する。
  `thread-anchor.test.ts` は末尾の同時成長を補正から除外することを検査する。位置保持の成功だけで
  巨大な実会話の滑らかさや待ち時間まで保証せず、別途入力・フレーム遅延を計測する。

### Markdownの表

- 表は共通のMarkdown描画とCSSで整える。行・列の罫線には透明な通常borderではなく
  `--ds-border-strong` を使い、見出しの半透明背景・交互の行背景で読み取りを助ける。
- 短い見出しやセル内コード（コミットID・ファイル名）を途中で折らない。説明文は自然に折り返し、
  収まらない表は専用の枠内で横スクロールさせる。会話全体を横にはみ出させず、内容は省略しない。
- 狭い幅・通常幅・文字サイズ変更時の折り返し、罫線、末列への到達を描画テストで検査する。

### Markdownのコードブロック・図・Alert

- コードフェンスは共通の `MarkdownPre`（`MarkdownBlocks.tsx`）で、言語ラベルとコピーボタンの見出し行を
  `pre` の上に置く。背景は外枠1枚だけにし、`pre` に背景を重ねない。`pre > code` の構造は変えない。
- Mermaidは閉じたフェンスだけを描画し、配信中に書きかけの図を組まない。対応6種はWorker（beautiful-mermaid）、
  それ以外は公式Mermaidを表示範囲付近に来たときだけUIスレッドで1件ずつ描く。SVGはshadow rootに入れて
  `<style>`・idを隔離し、script・イベント属性・外部リンク・`@import` を除く。描画できない場合はコードのまま残す。
- GitHub Alert（`> [!NOTE]` 等）は引用の形のまま左線とタイトルを状態色にする。脚注リンクはメッセージ内でジャンプする。
  `markdown-blocks-ui.test.ts` で検査する。

## 4. スクロールバー

### 見た目の条件

- 横バーは左端と右端、縦バーは上端と下端で、端まで移動したthumbの余白を揃える。
- 親Cardの角丸を考慮した端の余白を設ける。
  一番下・右まで移動しても、thumbの丸みや本体が欠けてはいけない。
- 縦横が同時に出ると右下の交差領域が片側の余白に加算される。その分も両軸で補正する。
- 横だけ、縦だけ、縦横両方、安定したgutterの有無で確認する。
- バーや余白を隠して不具合を取り繕わない。すべての内容へ到達できることを保つ。

### 実装の条件

- `styles.css` 冒頭の共通スクロールバー規則を再利用する。
  通常の端の余白は4px、バーの幅・高さは8px。
- 角丸のあるスクロール領域では、その要素に `--scrollbar-inset` を設定する。
  例：`--scrollbar-inset: var(--radius-sm)`。
  親の角丸を受ける内側のスクロール領域では、親のカーブと既存の内側余白も考慮する。
- 共通規則は各要素でinsetを初期化する。親に設定した値が子にも効くと想定しない。
- 内容のpaddingや透明borderを増やしても、track自体の端の余白の代用にはならない。
- 個別の `scrollbar-width: thin` や `scrollbar-color` は追加しない。
  Chromiumでは共通のWebKitスクロールバー装飾・track marginが効かなくなる。
  hoverなどの色変更も、共通のthumbの形・余白を維持する。
- xtermなど独自スクロールを実装するUIは、その実装と親の内側余白を確認する。
  ネイティブ用の規則が適用されると決めつけない。

## 5. ツール出力は約8行のプレビュー

- ターミナル出力、ファイル表示、検索結果、書き込み内容、編集差分を約8行に揃える。
- Grepの検索結果はファイル別にまとめ、一致行・行番号・前後の文脈を表示する。
  見出し・開閉・本文枠はEdit／Listと共通にし、件数は文脈行や同じ行内の複数一致を含めない。
  上限・切り詰め通知は残し、失敗や未知の出力形式は元のリテラル表示へ戻す。
- 固定pxで行数を近似せず、`lh` に基づく高さにする。文字サイズ変更に追従させる。
- 上下padding・区切り線・横スクロールバーの高さは、本文8行とは別に見込む。
- 超えた分は同じ枠内をスクロールする。データの切り捨てや「全文表示」用の別Cardで代用しない。
- 折り畳みと再展開では、既存の縦横スクロール位置・注釈・本文の保護を壊さない。
- この8行ルールは会話内のツール出力用。Markdownの一般的なコードブロックや
  対話型ターミナルダイアログ全体の高さまで一律8行にしない。
- 会話内ビジュアル（`show_widget`）は出力プレビューではなく本文なのて8行にしない。
  面は透明・枠なし（Cardにしない）、幅は通常736px／`wide` で1,024pxまで。
  必ず共通の `WidgetFrame` を使い（隔離・CSP・同時数の上限・高さの記憶）、個別にiframeを作らない。
  生成し直しでも最後に測った高さで枠を確保し、周囲を動かさない。`widget-ui.test.ts` で検査する。
- MCP Appsは通常のツール結果を置き換えず、共通 `WidgetFrame` で静的プレビューを併設する。
  プレビューは8行で枠内スクロール。「スクリプト・通信なし」をツール領域内に明示し、
  取得・失敗・再試行で枠の高さやComposerの位置を変えない。MCP表示はグローバルなscript許可と独立して
  常に静的sandboxを使う。隔離フレームには読み込み済みの共通スクロールバー規則を写して入れる。
  `mcp-apps-ui.test.ts` が実画素・遅延描画・通常結果の維持・8行・再試行を検査する。

## 6. Composerと状態変化

- Composerは縦方向の余白を重ねない。外枠の上下paddingは8px、添付・注釈欄の上は4px、
  入力欄の上下は各2px、ツールバーの上は2pxを基準とする。入力の最低高は固定32pxではなく
  `1lh + 4px` とし、文字サイズに追従させる。文字・送信ボタン・添付画像そのものは小さくしない。
  `composer-editor-ui.test.ts` が通常／新規チャット・狭い幅・文字拡大時の間隔と見切れなしを検査する。
- 入力のUndoは `Ctrl+Z`（`Meta+Z` も対応）、Redoは `Ctrl+Shift+Z` / `Ctrl+Y`。
  改行・補完・折り畳みペーストも履歴に含め、ペーストの本文と選択範囲を一緒に戻す。
  Undo履歴は下書きごとに最大100段階保持し、Pane切替で混ざらない。送信によるクリアでリセットする。
  `↑` はカーソルが先頭、`↓` は末尾（履歴呼び出し直後は先頭でも可）にあるときに、
  現在のチャットで読み込み済みのユーザー入力を辿る。最新より先へ戻ると未送信の下書きを復元する。
  呼び戻すのは本文だけで、現在の添付を置き換えたり、過去の画像・ファイルを勝手に添付しない。
  選択中・修飾キー付き・IME変換中は履歴を呼び出さず、スラッシュ補完の候補選択を優先する。
  `composer-editor-ui.test.ts` が本番Composerと新規チャットでキーボード操作を検査する。
- ファイルのドロップは入力欄だけでなくチャットPane全体（`.chat-shell`）で受け付ける。
  ドラッグ中はPane全面に `file-drop-overlay`（`--ds-bg-popover` の面・アクセント色の破線枠）を重ね、
  周囲のレイアウトは動かさない。新規・既存チャットとも画像以外のファイルも捨てずに添付する。
  Pane外へのドロップはWebView2に渡さず無視する。`file-drop-ui.test.ts` で検査する。
- Composerの下にテキストメッセージ系UIを描画しない。
  送信状態、エラー、モデル未選択案内、ヒント、ショートカット説明、
  拡張の `belowEditor` ウィジェットも対象。
- 空き領域の予約やCSSで隠す処置ではなく、描画そのものをなくす。
- 状態の有無でComposerや会話領域の高さ・位置を変えない。
- 必要なエラーは既存の通知UIに出す。新しい補足行を足さない。
- その他の状態表示でも、不要なレイアウトの跳ね・横幅の変化を避ける。
- 応答中の待機行（`RunningIndicator` / `.running`）は従来の固定文言「処理中…」を会話末尾に出す。
  スピナー・動詞の入れ替え・専用の高さを加えない。拡張の `setWorkingMessage` とシンボル指定は維持する。
  `running-indicator.test.tsx` と `transcript-ui.test.ts` が固定表示と拡張文言を検査する。
  デザインの候補は Storybook の **Chat/Activity/Running** だけに置く。
  Storybookでの比較・確認依頼を実画面への採用と扱わず、採用は別途ユーザーの確認を取る。
- Composerのコンテキスト表示は未取得時も「—」でなく、使用済みなら `0%`、残りなら `100%` とし、
  リングも数値に揃える。未取得・圧縮後の計測待ちの説明はアクセシブル名に残す。
  `context-indicator-ui.test.ts` で設定切替と実描画を検査する。
- Compactionは会話内の半透明Cardで示す。圧縮中だけアイコンを回転させ、通常の「処理中…」とは重複させない。
  手動圧縮も実行状態に関係なく表示し、完了・中断・失敗で圧縮中表示を解消する。
  保存済みの圧縮履歴は要約を遅延展開できる同じCardにし、トークン数は「圧縮前」と明記する。
  圧縮履歴を作業折り畳みの対象や作業件数に含めず、応答が折り畳まれていても表示する。
  `compaction` のChatRendererで差し替え可能にし、動きを減らす設定では回転を止める。
- Composerの操作ボタンは常に1個だけ描画する。応答中は入力（添付を含む）があれば送信、
  なければ停止に切り替える。送信待ち・停止確認中は無効なスピナーに置き換え、
  応答中の追加送信でも同じ規則を使う。Steeringがキューに受け付けられた時点で送信待ちは終了し、
  エージェントによる読み取りや履歴への反映を待たず停止（下書きがあれば送信）に戻す。
  切り替えでボタンやPickerの位置を動かさない。
- 送信結果が確認不能な入力を、会話内の送信待ち／Steeringの吹き出しとして残し続けない。
  通信失敗時は同じ送信ID・同じ内容で最大3回まで再試行し、ホスト側の受付台帳で二重実行を防ぐ。
  受付済み・実行中と確認できた入力や、別ホスト・別epochへ移った入力は再送しない。
  それでも確認不能なら本文・添付をComposerへ一度だけ戻し、新しい下書きを消さず既存通知で知らせる。
  確認不能を拒否と見なさず、確定済みの会話履歴は消さない。遅れて受付を確認した場合も編集済み下書きを消さない。
  同じセッション・epoch（明示的に引き継いだ場合はその移行先）の履歴に送信IDが確認できれば、
  受付RPCの応答や照会が失敗していても
  確認済みに戻す。再接続時にも照合し、古い「送信結果不明」で編集・再実行を塞ぎ続けない。
  本文一致や時間だけでは送信済みと判定しない。
- 送信結果が不明でも、実行の停止を確認できれば差し戻し・枝分かれで復旧できるようにする。
  受付結果の照会成功を復旧の前提にしない。停止が失敗・未確認なら履歴は変更しない。
  まだComposerへ返却していない未確認の本文・添付は元の送信に保持し、
  差し戻し・枝分かれ先へ自動送信・遅延反映しない。
  既にComposerへ返却済みの内容は通常の下書きとして引き継げるが、自動送信しない。
  差し戻して再送するのはユーザーが明示的に選んだメッセージだけにする。
- 受付済みのSteeringも、実行がSDK例外で終了した場合は停止時と同じ回収処理を通す。
  未処理の入力を保存してキューと待機表示を解消し、同じチャットで次の手動送信・再開を可能にする。
  通常のモデルエラーだけを回収対象にせず、失敗した入力を自動再送しない。
  回収記録を配信済みと扱わず、本文・添付を新しい下書きを保ったまま入力欄へ戻し、既存通知で知らせる。
  下書き保存後に復旧済みを記録し、同じ記録の再受信・画面再読み込みで二重に戻さない。
  受付が不明な入力は拒否と区別し、上記の有限回の通信復旧後にComposerへ戻す。未確認トレイへ放置しない。
  Composer下の補足行は追加しない。
  `send-controller.test.ts`・`steering-recovery.test.ts`・`session-resume-ui.test.ts` で再試行・回収・通知・二重実行防止を検査する。
- 応答中に送った割り込み（Steering）は、未読の間は会話に描かず、キューと同じトレイ（`MessageQueue` の
  `steering`、行は `.message-queue-steer`）の先頭に置く。SDKが個別に取り消せないため、行は読み取り専用で操作ボタンを出さない。
  エージェントが読んだ後（履歴に入った後）は会話の通常の `user-bubble` で描く。
  説明行（「割り込み待ち」等）をComposerの上下に足さない。
- SDKが自動で再試行した失敗は、エラーCard（`response-error`）ではなく1行の小さなチップ（`.response-retry`）で示す。
  背景は `--ds-tool-row-bg` の半透明、文字は `--ds-text-muted`。待機中だけ回転アイコンと「再試行中 n/上限 · 秒数」、
  済んだ試行はチェックと回数。元のエラー全文はチップの `aria-description` に持つ。上限到達・再試行しないエラーだけを通常のエラーCardにする。
- エラー・手動停止後の空のComposerは、送信と同じ位置・寸法の再開アイコンを使う。
  再開は言語にかかわらず `continue` だけを通常の送信経路で送り、過去の要求全体を機械的に再送しない。
  自動生成した再開指示は送信待ち・実行中・履歴再読込後も会話に描画しない。本文一致で通常の入力まで隠さず、
  送信IDと保存済みentryの識別情報で区別する。
  下書きがある場合は通常の送信を優先する。送信待ち・停止確認中・実行中は再開を重ねず、
  モデル未選択・下書き競合時の検証と既存の通知UIを維持する。
- サイドバーの折り畳まれたチャット一覧は、選択中のチャットも未ピン留め5件の枠に含める。
  古いチャットを選んだときだけ別枠で1行増やさず、ピン留めと起動中チャットを含めた表示件数・後続プロジェクトの位置を選択だけで変えない。
- チャット・プロジェクトの状態点の色は、失敗＝`--ds-error`（赤）、応答中＝`--ds-accent`（実行中のターミナルと同色）、
  入力待ち＝`--ds-warning`（オレンジ）、完了＝`--ds-success`（緑）。
- チャット・プロジェクトの状態点は、入力待ちを除きsnapshotのエラーを実行中色より優先する。
  完了通知の到着・既読化に依存せず赤で示し、エラーが解消された再実行では実行中色に戻す。
  診断情報のない過去のチャットも最新応答の停止理由から失敗を判定し、未起動のチャットも
  保存された失敗結果を既読で消さない。
  状態が切り替わっても淡い同系色の光を保ち、単なる塗りつぶしの点に変えない。脈動は実行中だけとする。
  失敗ラベルで未読と決めつけず、色・アニメーション・行の配置不変を描画テストで検査する。
  `session-status-ui.test.ts` でチャット・プロジェクト共通の全状態の光を実画素でも検査する。
- 自動表示するウィンドウタイトルバーは、ページを押し縮めず、外枠の上端だけを動かして
  表示範囲をクリップする。内側のページはウィンドウに追従する寸法と下端位置を保つ。
  開閉アニメーション中も本文・Composer・スクロール位置を動かさない。帯が開いている間は
  ページ上端が一時的に隠れる。サイドバーの開閉状態、履歴の先頭・途中・末尾で描画検査する。
  ホバーで開いた後は全辺の外側24pxまで保持し、さらに外へ出ても200msは閉じない。
  Windowsのタイリングで上端がクライアント領域より少し上に出ても保持するため、ウィンドウの
  `mouseleave` でも座標を捨てず同じ判定を使う。非フォーカス時は閉じる。
  保持範囲へ戻れば閉じる予約を取り消す。この余裕は閉じた帯の開く範囲や本文のクリック範囲を広げない。
  帯・クリップ境界・文字のフェードは共通のslowトークン（300ms）で揃え、閉じるフェード完了まで
  文字のvisibilityを維持する。`prefers-reduced-motion` では従来どおりアニメーションを止める。
  境界付近の保持・上端のmouseleave・再進入・範囲外での閉鎖も描画テストで検査する。
  サイドバーと本文の境界はPaneの区切りと同じく左右ドラッグ・矢印キーで幅を変え（200〜480px、ダブルクリックで260px）、
  幅は設定に保存する。最小幅より大きく狭めて離すとサイドバーを閉じ、直前の幅を保ったまま開閉ボタンで戻す。
  ドラッグ中は幅の遷移アニメーションを止めてポインターに直接追従させる。`sidebar-resize-ui.test.ts` で実入力を検査する。
  サイドバーの開閉ボタンは、開いている間はサイドバー右上、閉じている間はZenバーの左端に置き、
  ウィンドウ操作と同じ高さ・縦位置に揃える。Paneのwinbarに重ねて常時表示しない。
- 設定・Provider・Extension・Statisticsの画面は会話Paneの上に重ねて表示し、会話Paneをunmount・再構築しない。
  下の会話は `visibility: hidden` と `inert` で隠し、スクロール位置・入力欄・展開状態を保つ。
  `pane-updates-ui.test.ts` が切替時のDOM維持・スクロール位置・入力の遮断を検査する。
- ツール結果の画像は、その結果（ツール行）の中だけに表示する。応答の完了・停止・エラーを契機に
  回答末尾などへ再掲しない。`work-folding-ui.test.ts` が各終了状態で再掲なしを検査する。
- 画像Viewerの背景は動的配色のテーマ色でなく、無彩色の薄い暗幕（`rgb(32 32 32 / 45%)`）にする。
- Composerの添付画像はサムネイルをボタンにし、会話の画像と共通のViewerでプレビューする。
  未作成の新規チャットのComposerでも同じ貼り付け・ドロップ・プレビューを使い、初回送信へ画像を引き継ぐ。
  複数画像の切り替え・拡大・Escapeで閉じる操作を揃え、閉じたら元のサムネイルへフォーカスを戻す。
  削除ボタンは独立させ、プレビュー操作で下書きの変更・送信やComposerの配置変更を起こさない。
- 送信待ち（未読のSteeringと応答後のキュー）は、Composerの上端に下9pxを潜らせて接する1枚のトレイ
  （`MessageQueue`、`--ds-tile`＋`--ds-border`、下辺の枠なし・上だけ角丸、左右18px内側）に置く。
  見出し・タブ・開閉・件数・行番号は描画しない（ラベルはアクセシブル名）。Steeringが先、キューが後で、
  境目だけ `--ds-border-strong` の点線にする。行は両方とも同じ高さ30pxの1行（本文は「…」で省略）で、
  届く時期は行頭アイコンで示す：Steering＝紙飛行機（`--ds-accent`）、キュー＝`ListEnd`。高さは約3行で止め、超過分は枠内でスクロール。
  添付はクリップアイコンだけで数はアクセシブル名に持つ。キューの各行は左から時期アイコン・本文・添付・
  今すぐ送信（割り込み、紙飛行機アイコン）・編集・削除。並べ替えはドラッグとつまみ上の `Alt+↑/↓` の両方で行う。
  つまみは行頭アイコンと同じセルで、行のホバー・フォーカス時だけ `ListEnd` からつまみの絵に変わる（位置は動かさない）。

  送信を開始した行はつまみの位置にスピナーを出し、移動・割り込みはできない（列は空けたまま位置を変えない）。
  順番と割り込みはホストの送信待ち列で確定させ、表示だけを入れ替えない。
- 添付の読み込み中表示は、完了後と同じ左上の添付枠・寸法を使う。ページ全体の

### Provider使用量の常設表示

- サイドバーの使用量一覧は利用可能な横幅に追従し、1アカウント1行を基準とする。
  Providerごとの独立windowは同じ順番に保ち、値の大小で行の順番を入れ替えない。
- 制限が2つあるアカウントは1制限1行で2行にし、行数を値で変えない。
  各行は枠付きの横バーと%だけで、バーの塗りが容量、枠線がリセットまでの残り時間（右から減る）。
  リセットまでの時間と日時は行に文字で書かず、枠線とtooltip・ポップオーバーで示す。
  ホバーパネルのゲージも同じ塗り・枠線の描画を使い、容量とリセットまでの時間の意味を揃える。
- 見出しは「使用量」と更新ボタンのみ。「残り／使用済み」や更新経過タイマー・折り畳み時の要約を足さない。
  更新中と更新後10秒間は更新ボタンを無効にし、取得中だけアイコンを回転させる。
- 一覧は表示名順で固定し、使用率の変化で行を移動させない。Anthropicはpigのアカウントだけを表示し、Claude CLIを別行に追加しない。
- 枠線はリセットまでの残り時間で、時間が経つと右から短くなる。期間長が不明なら枠線を描かない。
  Mistralの枠線はリセット日時から前月の同日（存在しなければ月末）までの月次期間を使う。
  残高・キー予算・契約枠を混同せず、金額だけの応答に%の分母を仮定しない。
- 取得エラー時も最後の成功値・取得時刻を維持し、古い観測だと分かる表示にする。
  未取得・権限不足・無制限・0を同じ表示値に変換しない。
- Codexの制限枠はAPI・応答ヘッダーとも正の制限期間があるものだけを表示する。
  期間0・欠落のプレースホルダーを「secondary」等の残り100%の枠にしない。
  契約名やprimary/secondaryの位置で有無を決めず、有効な枠の使用率0%は表示する。
- 行の名前は同じProviderの複数アカウントで共通する先頭の語を省く（`OpenAI Personal` / `OpenAI Work` → `Personal` / `Work`）。
  1アカウントだけのProviderは省かず、各名前は最低1語残す。正式名はポップオーバーに出す。
- 一覧は横スクロールさせない。バー列は横幅に追従する固定幅（`clamp(64px, 45%, 112px)`）で取り、名前列を省略表示で縮める。
  %と残高の数値は名前より一段小さい `--text-4xs` を使い、%は右寄せの固定幅セルに置いて行間で揃える。
- 時間は言語非依存の `1h 12m` / `45m` / `12s`、日付は `12/1` とし、行のtooltipとポップオーバーに出す。
  「残り／使用済み」の設定は%とバーの塗りだけに適用し、枠線の時間や警告しきい値の意味を反転しない。
- `provider-usage-ui.test.ts` で実コンポーネントの幅追従・8pxバー・行高・設定切替・透過Card・最終行への到達を検査する。

### 他アプリの履歴取り込み

- 設定の専用カテゴリーで、取り込み元を共通の `segmented-control` タブで切り替え、
  「タイトル検索・プロジェクト絞り込み・並び替え → 会話選択 → 取り込み」を通常導線にする。
  数百件を前提に、一覧だけを枠内でスクロールさせる。
  端末に保存された履歴は直接読み、ログイン・JSON・Cookie等の内部形式をユーザーに用意させない。
  ファイル取り込みは任意の代替手段として同じ並びに置く。
- 取り込み失敗は件数だけで済ませず、失敗した会話名と具体的な原因を既存通知UIに残す。
  取り込み元の一覧取得エラーも原因を表示し、本文や認証情報は診断へ含めない。

### 検索パレット（何でも検索）

- `search.open`（既定 `Ctrl+K`、設定で変更可）でウィンドウ内のモーダル `<dialog>` として開く。
  閉じている間は描画しない。別OSウィンドウやグローバルホットキーにはしない。
- 面は `--ds-bg-popover` とぼかし・共通の影。全体 `opacity` は使わない。
- 結果一覧は高さ固定で枠内スクロール。件数・0件・索引作成中の表示で、パレットの大きさや位置を変えない。
  索引作成中の表示はパレット内のフッターに出し、エラーは既存の通知UIに出す。
- チャット名・設定・操作・ページは同じfuzzy照合（`shared/fuzzy.ts`）で1つのリストに並べる。
  空クエリでは最近のチャットだけを出す。会話本文はfuzzyにせず、空白区切りの語をすべて含む部分一致
  （Bun側のSQLite索引）で、名前系の結果の後ろに新しい順で並べる。
  索引による候補抽出を足しても、全語の正確な部分一致確認の前に件数を制限しない。
  短い日本語・記号のリテラル検索とジャンプ先を維持し、`search-query.test.ts` / `search-index.test.ts` で
  旧SQLとの結果一致と索引を使う実行計画を検査する。
  索引作成はファイル全体のdecode/splitを先に済ませず、読込・完全なJSONL行の解析・SQLite登録まで
  分割する。UTF-8の途中や未完了行でcheckpointを進めず、登録行とバイト位置を同じtransactionで保存する。
  読込中の削除・置換・保存先変更・closeで古い処理を再反映しない。`search-jsonl.test.ts` と
  `search-index-streaming.test.ts` が境界・中断再開・世代変更・全文の一致を検査する。
- 設定項目を足したら `settings-search.ts` の `settingTargets` に登録し、行に `data-setting` を付ける。
  `search-ui.test.ts` が全カテゴリの描画で全idの存在を検査する。
- 結果へのジャンプは対象をスクロールして表示・フォーカスし、`search-target` の輪郭を一時的に出す。
  輪郭は `outline` だけで、周囲のレイアウトを動かさない。会話の該当メッセージは必要な分の履歴を読み込み、
  折り畳まれた作業範囲は開く。現在のブランチにないメッセージは通知UIで知らせる。

### 通知の既読

- チャットの正常完了通知は、そのチャットの履歴を表示した時点で自動既読にし、トーストも閉じる。
  履歴が読めるなら、実行環境の起動完了までは待たない。
- 表示するチャットの判定は画面と既読処理で揃える。別チャットのバックグラウンド起動で既読を止めない。
- 非表示・非フォーカスのウィンドウ、別画面、まだ履歴が表示されていないチャットは既読にしない。

## 7. 入力を妨げない描画

- 保存済み会話の閲覧・履歴追加読込・下書き編集ではSDK・拡張・MCPを起動しない。
  送信・モデル操作・明示的な拡張補完など、実行環境が必要な操作でのみ起動し、送信CASより先に完了させる。
- 自動休止は会話を閉じる操作ではない。`ready: false` の起動中previewや空画面に置き換えず、
  会話DOM・読込済み履歴・選択Range・スクロール・Composer・IMEを保持する。
  実行epochと表示用のReact keyを分離し、休止だけでChatを再mountしない。
  空の下書きmirrorの所有者移行echoを別編集と扱って、遅いローカル入力に偽の競合を作らない。
  `runtime-suspension-ui.test.ts` とdraft/runtime回帰テストで検査する。
- 再接続で休止中の全会話本文を一斉に読み直さない。表示中Paneの本文がないか履歴revisionが異なる場合だけ
  権威あるSnapshotを取得する。休止可否は全Root・全Pane・下書き・未確認送信・承認・terminalを保護して判定し、
  使用状態や拡張のbackground処理が不明な場合は休止しない。
- 閉じているPickerの重い一覧は、CSSで隠すだけでなく開いたときに描画する。
  開閉時のフォーカスと、開いた状態の高さ・検索・キーボード操作は維持する。
  閉じている間は一覧の生成・検索用の全件走査も行わず、トリガーの表示名はアカウントの
  メタデータだけから取得する。本文の連続配信中も同じ条件を検査する。
- Composerの入力でモデル一覧や会話履歴を再計算・再描画しない。子のmemo化だけでなく、
  渡すcallbackとContextの参照も安定させる。
  モデルPickerには本文・context使用量を含むSnapshot全体を渡さず、選択・アカウント・
  カタログ等の必要なmetadataだけを渡す。開いている間も本文更新で検索・focusを変えない。
  同じ表示カタログは不変データとして共有できるが、SDKランタイム・認証情報は共有しない。
  アカウント・プロジェクト・上限・effort設定による内容の違いは必ず維持する。
- 文字だけの下書き同期で画像を全量再送しない。RPC応答だけでなく、拡張通知のechoも検査する。
  参照元がない場合は空画像で上書きせず、同じaddressの権威ある下書きを取得し、revisionとローカル編集を保護する。
- 高頻度の状態更新ごとに一覧のディスク再探索を起動しない。完了・追加削除・metadata変更と、
  進捗表示だけの更新を分ける。外部CLI変更を見つける明示更新・focus時の再探索は維持する。
  一覧専用キャッシュでも毎回ディレクトリとファイル属性を確認し、差し替え・縮小・削除・保存先変更を
  反映する。途中書き込みや読み取り失敗を負のキャッシュとして確定せず、本文検索用の全文は保持しない。
- 未反映の送信がないとき、表示・送信照合のためだけに全履歴のrequest IDを走査しない。
  必要な集合は不変のrecords配列単位で共有し、request IDの変更・削除では新しい配列から計算する。
  WeakMapのキーから過去の本文を保持し続けない。`transcript-requests.test.ts` と
  `pane-updates-ui.test.ts` が共有・無効化・送信なしの走査0回を検査する。
- IPCで複製された保存済みentryは、同じepoch・履歴revisionの中だけ参照を再利用する。
  履歴追加でbranchId・order・requestIdなどが変わっても、不変本文とツール状態は再利用し、
  envelopeの変更・削除は必ず反映する。配信中のentry、更新されたツール状態、別branchの内容を古い表示で置き換えない。
  envelope・完了tool・ID順序の省略には正確な直前sequenceも要求する。取得済みの過去履歴と
  wire tailの件数・tool ID集合は分けて保持し、履歴prepend・参照共有・再接続でも混同しない。
  未知の参照・重複・基底欠落は部分反映せず、完全snapshotへ復旧する。
  `snapshot-reuse.test.ts` が全量oracle、metadata/field削除、履歴結合、容量fallbackと保持解除を検査する。
- 生成中の本文・思考・ツール出力の追記は、同じowner・履歴revision・配信sequenceの基底にだけ適用する。
  訂正・短縮・未知の出力構造は全文で置換し、差分欠落では今の本文と下書きを保ったまま完全snapshotを取得する。
  完全snapshotを返すRPCは送信側の差分基底もリセットし、復旧要求を繰り返さない。表示の更新間隔は変えない。
  読み込み済みの過去履歴の索引・prefixは本文更新ごとに作り直さず、履歴追加・境界変更・分岐では再検証する。
- 作業折り畳みの派生計算は、同じ履歴revisionの保存済み共通prefixだけ再利用する。
  変更を含む応答の先頭から再計算し、履歴の追加読み込み・編集・並べ替え・分岐・liveから保存IDへの移行では
  共通部分を確認できなければ全計算に戻す。`work-index.test.ts` が既存計算との一致と完了本文の再検査0回を、
  `work-folding-ui.test.ts` が折り畳み・全文コピー・検索ジャンプ・履歴追加時の実描画を検査する。
- Markdown用のコンポーネント型を描画ごとに作り直さない。配信中も変更のないコードのDOM、
  選択範囲、ハイライト処理を維持する。
  解析済みHASTの同一参照はmounted instance内で後処理を再利用してよいが、別メッセージのJSX/DOMや
  stateを共有しない。入力変更・画像Viewerの状態・URL安全処理・拡張Rendererの切替を維持する。
  `render-reuse-ui.test.ts` が同じtreeの再走査0回とDOM・選択・注釈用Range・画像・拡張切替を検査する。
- Markdownの解析待ちでは、段落間の改行を境に表示済みの書式を生テキストへ戻さない。
  見出し・箇条書き・引用の同じ行への追記は既存ブロック内に表示し、一時的な別行を作らない。
  解析完了前後の高さ・書式付きDOM・選択範囲を描画テストで検査する。
  KaTeX変換後も元Markdownの数式scopeの位置を保持し、後ろの文章の解析待ちで完成済み数式を
  生TeXへ戻さない。生成HTML内のoffsetを流用せず、未閉鎖数式・math fenceのEOFを確定境界にしない。
  配信中の未閉鎖display数式は、同じliteralノードに最新sourceと改行を表示し、追記のたびに
  不完全な組版と生TeXを往復させない。閉じた式は組版し、停止・完了時は通常の全量解析で確定する。
  配信中／確定の解析結果は別キーにし、遅れた配信中の結果で最終表示を上書きしない。
  `render-retention-ui.test.ts` がWorker保留中の数式DOM・高さ・選択／Rangeをframeごとに検査する。
- チャット・ファイル出力・編集差分・ANSI出力の更新では、再解析待ちで全文を無色に戻さない。
  共通のハイライト処理で変更前と一致する先頭部分の色とDOMを保ち、追加・変更部分だけを
  一時的に無色で表示する。本文は常に最新の内容とし、言語変更や古い非同期結果で旧本文・旧色を
  復活させない。変更箇所より後は字句状態が変わりうるため、新しい解析結果で確定する。
  描画テストで解析完了前の色・DOM・本文も検査する。
- 高コストなハイライト・Markdown・数式解析はWorkerへ出し、Workerごとに同時実行1件とする。
  不要になった待機ジョブは破棄し、古い結果で新しい本文を上書きしない。最終的な書式・安全なURL処理・
  コード用コンポーネントは既存と一致させる。未解析の追加部分もescaped textで保持し、全文表示ボタンや切り捨てで代用しない。
  Workerの異常終了は次の要求で再生成し、古いWorkerの応答・エラーを新しい世代へ適用しない。
  起動禁止などの連続失敗には上限を設け、転送済みジョブを自動再送しない。
  転送済みの元入力やキャンセル済みの待機入力をキュー・クロージャで保持し続けない。Workerへ渡した内容・
  順序・キャンセルの分離は維持する。`render-worker-queue.test.ts` が元入力のGCと転送内容を検査する。
  Workerキューの解放を理由に会話本文や表示中の解析結果を削減しない。
- 構文ハイライトの共有キャッシュは32件・推定16MiBを上限とし、解析完了時にも容量を再評価する。
  未使用の完了結果を優先してLRUで解放し、単独で予算を超える結果は呼出元へ返すが共有保持しない。
  表示利用はeffectのcleanupまで追跡し、Promise待機人数と混同しない。全件が表示中でも共有索引は
  予算内に収めるが、各表示が持つtokens・色・DOMは消さず、再描画や再解析を強制しない。
  in-flightの同一入力共有と利用者ごとのcancelは容量制御と分離する。`highlight-cache.test.ts` が
  容量・LRU・lease・cancel・遅い旧結果を、`render-retention-ui.test.ts` がeviction後の色・全文・DOM・選択を検査する。
- 構文解析済みの完全な行prefixは、入力文字列・言語・解析設定が一致するときだけ状態を再利用してよい。
  書きかけの最終行は含めず、変更・短縮・言語変更では一致を確認できない範囲を再解析する。
  CRLF・Unicode・token offset・複数行の字句状態を全文解析と一致させる。ANSIには通常言語の状態を使わない。
  Worker内の直前prefix1件に留め、履歴表示キャッシュの破棄やWorkerの同時実行数変更で代用しない。
  `syntax-engine.test.ts` が全対応言語の全文oracle、編集・短縮・交互/同時入力と既存結果の非破壊性を検査する。
- Worker化はfallbackだけでテストを通さない。本番Viteのinline WorkerでもDOM依存がなく動くこと、
  重い解析中に実入力とUI heartbeatが処理されることを描画検査する。単なる解析の所要時間と入力遅延を混同しない。
- 出力DOMの削減では同じスタイルの連続テキストをまとめ、全文・改行・色の境界・選択／コピーを維持する。
  8行previewの高さ制限だけでDOM件数も減るとは扱わない。
  行をまとめたtext node全体の置換は、同じnodeが残っていても選択・注釈用Rangeを失わせ得る。
  追記・完了への移行を含めて実ブラウザで確認し、単なる全文一致だけを互換性の根拠にしない。
  保存済み本文・確定ツール結果の初回マウントでは、同じ装飾のspanを行をまたいで共有してよいが、
  行ごとのtext nodeは保持する。配信中にマウントした内容を完了時にまとめ直さない。
  背景・太字・斜体・下線等のある空白を無装飾扱いせず、差分の行幅いっぱいの背景も維持する。
  更新可能な設定Cardや拡張Rendererにはこの不変本文用の最適化を引き継がせない。
  `output-dom-ui.test.ts` が要素数とText nodeを含む総数の減少、字形・色・行背景・スクロール寸法、
  全選択コピー・逆方向選択・Range・追記・完了・本番Chat/ツール経路・拡張切替を検査する。
- 標準のコード・差分は色だけのtokenごとに要素を作らず、CSS Custom HighlightのRangeで色を描く。
  字体・文字装飾のspanと差分の全幅行背景は残す。全履歴へRangeを一括登録せず、表示範囲と先読み分に絞る。
  これは色指定の限定であり、本文DOM・履歴の仮想化や切詰めではない。配信開始時から同じ構造を維持し、
  完了時に組み替えない。文字の更新はCharacterDataの最小差分にし、選択・注釈用Rangeを全文代入で失わせない。
  API非対応環境・拡張Renderer・設定Cardでは従来描画を使う。unmount時はRange・style・observerを解放する。
  `syntax-ranges-ui.test.ts` がnative全選択、実画素、色・字体、逆方向選択、追記、実注釈、
  trusted wheel、先読み範囲の色、Range数と後片付けを検査する。
  `syntax-streaming-ui.test.ts` は構文/Markdown Workerの両方を意図的に保留し、逐次追加・改行・
  未閉鎖fenceの完了までフレームごとの既存色・DOM・選択を検査する。選択で色抜けを隠さないよう、
  未選択glyphの実画素も比較し、既存の色を消すと検査が失敗する感度対照を含める。
- `transcript-ui.test.ts` は、1000モデルの新規Composerで入力中のcatalog再走査が0回、
  IPC更新で変更のないツールの再描画が0回、変更されたツールだけ更新されることも検査する。
- 常時（無限）に動くアニメーションは、要素自身の `opacity` / `transform` だけをkeyframeに書く。
  `box-shadow` 等の補間や疑似要素のアニメーションは合成処理されず、実行中のチャットがある間
  ページ全体のスタイル再計算を毎フレーム起こす（実行中の点で毎秒約70回→約8回）。光彩は静的な影にして
  要素と一緒にフェードさせる。形が変わる光彩（シェルの状態点の光→リング）は、影ごとに子要素へ分けて
  `opacity` でクロスフェードする（疑似要素は使わない）。色の濃淡の点滅は背景色でなく `opacity` にする。
  `infinite-animations.test.ts` が全CSSの無限アニメーションを、`session-status-ui.test.ts` が実行中の点を検査する。
