# UI共通ルール

UIの追加・変更・レビュー時に適用する。スクリーンショットごとの場当たり的な修正ではなく、
同じ役割のUIに同じ基準を適用するための規約。
新しい共通の指摘・合意は、実装と同時にここへ追記する。

## 自動検査（文書だけに依存しない）

| 検査 | 自動で止めるもの |
| --- | --- |
| `pnpm lint` → `lint:ui` | Cardへの不透明な背景・全体opacity、許可トークン自体の不透明化、inline styleでの背景指定、個別のスクロールバー形状・native thin/color指定 |
| `pnpm test:ui` | 実描画でのスクロールバーの端の非対称・見切れ、Cardの背景alphaと全体opacity、出力枠の左右の不整列、8行上限、サイドバーアイコン列の上下余白、ターミナル枠内の最低1pxの隙間 |
| CI / Release | 毎回は静的Lint・軽量テスト・Webビルド。重い実描画は毎日／手動の `Regression` に分離 |

- 静的検査は `apps/desktop/scripts/ui-style-rules.ts`。CSS・セレクター・JSXをASTで解析する。
  `check-ui-styles.ts` が本番の `mainview` 配下を走査し、違反箇所をファイル・行番号付きで出力する。
- 新しい通常Cardは `*-card` / `ui-card` クラス、または `data-ui-surface="card"` を使う。
  `session-panel` と `response-error` もCardとして検査する。任意の名前から役割を推測する検査ではない。
- 背景は許可された半透明トークンを共有CSSから指定する。Cardのinline styleはレイアウト用途に限る。
  動的なstyleオブジェクトやspreadで検査を迂回しない。
- UI変更時は、通常CIの成否とは別に `pnpm test:ui` を実行する。`Regression` のUIジョブも
  同じ検査を実行し、ブラウザ不在はスキップせず失敗する。検査頻度の分離であって削除ではない。
- 描画検査は `transcript-ui.test.ts`。スクリーンショットのthumbのピクセルと実要素の寸法を測る。
  スクリーンショット全体の一致だけで判定する方式ではない。
- 新しいCard・スクロールUIは描画fixtureにも追加する。検査対象を外す・スキップする・
  許容誤差を広げることを、不具合修正の代わりにしない。
- すべての美的判断を自動判定できるわけではない。新しい指摘のうち数値化・ルール化できるものは、
  文書だけで済ませずLintの違反例テストか描画の回帰テストへ追加する。

## 1. 既存の見た目と共通実装を使う

- 色・文字・角丸は `apps/desktop/src/mainview/tokens.css` のトークンを使う。
  似た色や角丸を個別にハードコードして別体系を作らない。
- 同じ役割の枠・操作・スクロールには、既存コンポーネントと共通CSSを使う。
- 同種の問題を見つけたら、会話、ツール出力、サイドバー、設定、通知、Picker、
  ダイアログ、セッションパネルも横断して確認する。
- 既存実装の逸脱は、新規UIでも逸脱してよい根拠にはしない。
  共通ルールから外れる新しいデザインは、先にユーザーに確認する。

### 動的配色とカラーピッカー

- 設定に保存するのは不透明なsRGBのseed色だけ。Material Color UtilitiesのTonalSpotから
  `dynamic-theme.ts` で共通 `--ds-*` トークンへ変換し、画面ごとに配色計算を追加しない。
  無彩色seedの背景・アクセントはMonochromeにする。形・文字・余白のトークンは変更しない。
- 失敗色はMaterialのError、成功・警告は緑／アンバーの追加TonalPaletteをseedへharmonizeする。
  Primary上の文字には専用の `--ds-on-accent` を使い、背景色で代用しない。
- 動的配色でもCardのalphaを維持する。任意の壁紙・透明度でコントラストを保証できると扱わず、
  seedの極端値・不透明度・背景効果ごとに実描画を確認する。
- コードの構文色はCSS変数で既存DOMに反映し、色変更だけで再解析・再マウントしない。
  ANSIの色番号・明示RGBはテーマに合わせて置換しない。
- カラーピッカーは共通 `ColorPicker` を使う。Popoverは半透明背景・blur・共通角丸／影を再利用し、
  top layerでCardのクリップを避ける。色面・色相・HEX・プリセットを備え、キーボード操作とEscapeを保つ。
  色面の白／黒・色相スペクトル・色見本は編集対象そのものなのでUI配色トークン化の対象外。
- `dynamic-theme.test.ts` で色生成・コントラスト・Cardのalphaを、`dynamic-theme-ui.test.ts` で
  実際の設定・ピッカー操作・透過・配置不変・構文DOMの保持・ANSI不変を検査する。

## 2. Cardの背景は半透明のレイヤー

通常のCardは、ウィンドウの背景・透過感を引き継ぐ薄い重ね塗りにする。
不透明な色の板を置いて、背景から切り離さない。

| 用途 | 基準 |
| --- | --- |
| 設定・一覧・情報Card | `--ds-tile`、必要に応じて `--ds-elevation-stroke` |
| 控えめなツール・状態の枠 | `--ds-tool-row-bg` |
| Cardのhover | `--ds-tile-hover` など既存の状態トークン |
| 浮いているメニュー・Popover | `--ds-bg-popover` と既存のぼかし・影 |
| コード・ターミナル | 共通CSSの半透明背景レイヤーを再利用 |

- 背景色のalphaで透過させる。Card全体に `opacity` を付けて文字やアイコンまで薄くしない。
- シェルのミニターミナル（`.tool-term`）は、状態色（実行中・成功・失敗）を約7%混ぜた半透明の面と
  同系色の1pxリングで状態を示し、ログはその内側の一段暗い半透明層に置く。状態表示は右上の
  小さな点と所要時間（失敗時は終了コード）。実行中は点がゆっくり脈動し、ログ末尾の四角い
  キャレットがゆっくり点滅する。どちらも `prefers-reduced-motion` では止める。
  出力更新や一時IDから保存済みIDへの切り替えで状態点・キャレットを再マウントせず、
  アニメーションの位相と経過時間を維持する。Reactのキーは `liveToEntry` の対応を使って維持し、
  検索・操作用のrecord IDは保存済みIDへ更新する。
  `transcript-ui.test.ts` でbash／PowerShellの連続更新・保存時のDOM・開始時刻・経過時間を検査する。
- 通常のCardに `--ds-bg-elevated-opaque` や不透明な `--ds-bg-secondary` を流用しない。
- `background: transparent` だけで枠の区別を失わせることも、半透明Cardの代用にはしない。
- 背景レイヤーを無目的に入れ子にして、不透明に近づけない。
- 既存のモーダル・ネイティブ選択UI・対話型ターミナルなど、可読性のために不透明な面を
  使っている専用UIは別扱い。通常のCardへその例外を広げない。
- Acrylic / Mica / 透明背景やウィンドウの不透明度設定を変えても、
  背景との一体感と文字の可読性を両立させる。

## 3. 余白・枠・アイコンの整列

- 同じ階層の枠は左右端を揃える。枠ごとに幅やインデントを変えない。
- ターミナルの内側には最低1pxの余白を設け、スクロール領域を外枠のリングに密着させない。
- ターミナルの外枠は、ファイル表示・書き込み・編集差分の本文枠と同じ左右端にする。
  現在の共通本文インデントは22px。見出しのアイコン位置とは区別する。
- アイコンだけの操作は、当たり判定の中央に配置する。状態表示用の空枠を残さず、左右・上下のpaddingを対称にする。
- アイコン列は、ボタンの当たり判定を含めた領域の上下に同程度の余白を取る。
  サイドバー下部は上12px・下12pxが基準。
- 応答フッターのホバー操作はモデル情報と同じ行に置き、非表示の操作専用行で空白を作らない。
  モデル切り替えの区切り線の上は直前のメッセージ・フッターの余白を使い、余白を重ねない。
- 空きができる片側だけにpaddingを足す、負のmarginでその場だけ揃える、といった補修をしない。
- 角丸のある親子では、子の背景・枠・スクロールバーを親のカーブに食い込ませない。
- 幅が狭いとき、長いファイル名やコマンドでも整列を崩さない。
  省略表示・折り返し・枠内スクロールを役割に応じて使う。

### Pane

- PaneはCard化せず、共有背景を1pxのDividerで区切る。境界はドラッグ・矢印キーで調整する。
- Pane上部にタイトル・分割操作の専用ヘッダーやその予約領域を置かず、本文に全高を使う。分割・閉鎖は既存のショートカットを使う。
- 分割はフォーカス中のpaneを対象とし、別方向はその中だけを分割する。同方向の追加は兄弟を均等配置する。
- フォーカス移動・分割・サイズ変更で会話と下書きのDOMを保持する。Paneを閉じてもセッションは削除・停止しない。
- 各Paneは自分のSnapshotを購読し、非アクティブでも更新を続ける。他チャットの更新や起動進捗で
  無関係な本文を再描画しない。`pane-updates-ui.test.ts` が本番Appで本文の再読取0回、IME中の文字・
  カーソル、独立したスクロール位置、フォーカス・リサイズ時のDOM保持、epoch切り替えを検査する。

### Markdownの表

- 表は共通のMarkdown描画とCSSで整える。行・列の罫線には透明な通常borderではなく
  `--ds-border-strong` を使い、見出しの半透明背景・交互の行背景で読み取りを助ける。
- 短い見出しやセル内コード（コミットID・ファイル名）を途中で折らない。説明文は自然に折り返し、
  収まらない表は専用の枠内で横スクロールさせる。会話全体を横にはみ出させず、内容は省略しない。
- 狭い幅・通常幅・文字サイズ変更時の折り返し、罫線、末列への到達を描画テストで検査する。

## 4. スクロールバー

### 見た目の条件

- 横バーは左端と右端、縦バーは上端と下端で、端まで移動したthumbの余白を揃える。
- 親Cardの角丸を考慮した端の余白を設ける。
  一番下・右まで移動しても、thumbの丸みや本体が欠けてはいけない。
- 縦横が同時に出ると右下の交差領域が片側の余白に加算される。その分も両軸で補正する。
- 横だけ、縦だけ、縦横両方、安定したgutterの有無で確認する。
- バーや余白を隠して不具合を取り繕わない。すべての内容へ到達できることを保つ。

### 実装の条件

- `styles.css` 冒頭の共通スクロールバー規則を再利用する。
  通常の端の余白は4px、バーの幅・高さは8px。
- 角丸のあるスクロール領域では、その要素に `--scrollbar-inset` を設定する。
  例：`--scrollbar-inset: var(--radius-sm)`。
  親の角丸を受ける内側のスクロール領域では、親のカーブと既存の内側余白も考慮する。
- 共通規則は各要素でinsetを初期化する。親に設定した値が子にも効くと想定しない。
- 内容のpaddingや透明borderを増やしても、track自体の端の余白の代用にはならない。
- 個別の `scrollbar-width: thin` や `scrollbar-color` は追加しない。
  Chromiumでは共通のWebKitスクロールバー装飾・track marginが効かなくなる。
  hoverなどの色変更も、共通のthumbの形・余白を維持する。
- xtermなど独自スクロールを実装するUIは、その実装と親の内側余白を確認する。
  ネイティブ用の規則が適用されると決めつけない。

## 5. ツール出力は約8行のプレビュー

- ターミナル出力、ファイル表示、書き込み内容、編集差分を約8行に揃える。
- 固定pxで行数を近似せず、`lh` に基づく高さにする。文字サイズ変更に追従させる。
- 上下padding・区切り線・横スクロールバーの高さは、本文8行とは別に見込む。
- 超えた分は同じ枠内をスクロールする。データの切り捨てや「全文表示」用の別Cardで代用しない。
- 折り畳みと再展開では、既存の縦横スクロール位置・注釈・本文の保護を壊さない。
- この8行ルールは会話内のツール出力用。Markdownの一般的なコードブロックや
  対話型ターミナルダイアログ全体の高さまで一律8行にしない。

## 6. Composerと状態変化

- Composerの下にテキストメッセージ系UIを描画しない。
  送信状態、エラー、モデル未選択案内、ヒント、ショートカット説明、
  拡張の `belowEditor` ウィジェットも対象。
- 空き領域の予約やCSSで隠す処置ではなく、描画そのものをなくす。
- 状態の有無でComposerや会話領域の高さ・位置を変えない。
- 必要なエラーは既存の通知UIに出す。新しい補足行を足さない。
- その他の状態表示でも、不要なレイアウトの跳ね・横幅の変化を避ける。
- チャット・プロジェクトの状態点は、入力待ちを除きsnapshotのエラーを実行中色より優先する。
  完了通知の到着・既読化に依存せず赤で示し、エラーが解消された再実行では実行中色に戻す。
  失敗ラベルで未読と決めつけず、色・アニメーション・行の配置不変を描画テストで検査する。
- 自動表示するウィンドウタイトルバーは、ページを押し縮めず、外枠の上端だけを動かして
  表示範囲をクリップする。内側のページはウィンドウに追従する寸法と下端位置を保つ。
  開閉アニメーション中も本文・Composer・スクロール位置を動かさない。帯が開いている間は
  ページ上端が一時的に隠れる。サイドバーの開閉状態、履歴の先頭・途中・末尾で描画検査する。
- 添付の読み込み中表示は、完了後と同じ左上の添付枠・寸法を使う。ページ全体の
  ローディング表示を流用しない。画像の有無が不明なクリップボード照会では仮の枠を出さず、
  失敗は既存の通知UIに出す。読み込み前後の位置・寸法と空の照会を描画テストで検査する。
- モデルPickerの一覧領域は、同じウィンドウサイズでは高さを固定する。最近使用・アカウントの
  切り替え、検索結果0件、未接続・ロック状態でも伸縮させない。モデル一覧とアカウント列は
  それぞれ枠内でスクロールし、件数が多くても全項目へ到達できるようにする。
- 会話の最下部へ戻る操作は、上へスクロールしている間だけComposerの上に重ねて表示する。
  表示の有無で会話やComposerを動かさず、クリック後は新しい返信への自動追従を再開する。

### Provider使用量の常設表示

- サイドバーの使用量一覧は利用可能な横幅に追従し、1アカウント1行・18px二重リングを基準とする。
  Providerごとの独立windowは同じ順番に保ち、値の大小でリング位置を入れ替えない。
- 見出しは「使用量」と更新ボタンのみ。「残り／使用済み」や更新経過タイマー・折り畳み時の要約を足さない。
  更新中と更新後10秒間は更新ボタンを無効にし、取得中だけアイコンを回転させる。
- 一覧は表示名順で固定し、使用率の変化で行を移動させない。Anthropicはpigのアカウントだけを表示し、Claude CLIを別行に追加しない。
- 内周は容量、外周はリセットまでの時間。どちらも12時を起点に反時計回りに描く。
  Mistralの外周はリセット日時から前月の同日（存在しなければ月末）までの月次期間を使う。
  それ以外で期間長が不明なら外周の値は作らない。
  残高・キー予算・契約枠を混同せず、金額だけの応答に%の分母を仮定しない。
- 取得エラー時も最後の成功値・取得時刻を維持し、古い観測だと分かる表示にする。
  未取得・権限不足・無制限・0を同じ表示値に変換しない。
- 時間は言語非依存の `1h 12m` / `45m` / `12s`、日付は `12/1` とする。
  日付の月・日にはそれぞれ2桁分の幅を取り、桁数が変わっても `/` の位置を列内で揃える。
  「残り／使用済み」の設定は数値と内周だけに適用し、外周の時間や警告しきい値の意味を反転しない。
- `provider-usage-ui.test.ts` で実コンポーネントの幅追従・18px・行高・設定切替・透過Card・最終行への到達を検査する。

### 通知の既読

- チャットの正常完了通知は、そのチャットの履歴を表示した時点で自動既読にし、トーストも閉じる。
  履歴が読めるなら、実行環境の起動完了までは待たない。
- 表示するチャットの判定は画面と既読処理で揃える。別チャットのバックグラウンド起動で既読を止めない。
- 非表示・非フォーカスのウィンドウ、別画面、まだ履歴が表示されていないチャットは既読にしない。

## 7. 入力を妨げない描画

- 閉じているPickerの重い一覧は、CSSで隠すだけでなく開いたときに描画する。
  開閉時のフォーカスと、開いた状態の高さ・検索・キーボード操作は維持する。
- Composerの入力でモデル一覧や会話履歴を再計算・再描画しない。子のmemo化だけでなく、
  渡すcallbackとContextの参照も安定させる。
- 文字だけの下書き同期で画像を全量再送しない。RPC応答だけでなく、拡張通知のechoも検査する。
  参照元がない場合は空画像で上書きせず、同じaddressの権威ある下書きを取得し、revisionとローカル編集を保護する。
- 高頻度の状態更新ごとに一覧のディスク再探索を起動しない。完了・追加削除・metadata変更と、
  進捗表示だけの更新を分ける。外部CLI変更を見つける明示更新・focus時の再探索は維持する。
- IPCで複製された保存済みentryは、同じepoch・履歴revisionの中だけ参照を再利用する。
  配信中のentry、更新されたツール状態、別branchの内容を古い表示で置き換えない。
- Markdown用のコンポーネント型を描画ごとに作り直さない。配信中も変更のないコードのDOM、
  選択範囲、ハイライト処理を維持する。
- Markdownの解析待ちでは、段落間の改行を境に表示済みの書式を生テキストへ戻さない。
  見出し・箇条書き・引用の同じ行への追記は既存ブロック内に表示し、一時的な別行を作らない。
  解析完了前後の高さ・書式付きDOM・選択範囲を描画テストで検査する。
- チャット・ファイル出力・編集差分・ANSI出力の更新では、再解析待ちで全文を無色に戻さない。
  共通のハイライト処理で変更前と一致する先頭部分の色とDOMを保ち、追加・変更部分だけを
  一時的に無色で表示する。本文は常に最新の内容とし、言語変更や古い非同期結果で旧本文・旧色を
  復活させない。変更箇所より後は字句状態が変わりうるため、新しい解析結果で確定する。
  描画テストで解析完了前の色・DOM・本文も検査する。
- 高コストなハイライト・Markdown・数式解析はWorkerへ出し、Workerごとに同時実行1件とする。
  不要になった待機ジョブは破棄し、古い結果で新しい本文を上書きしない。最終的な書式・安全なURL処理・
  コード用コンポーネントは既存と一致させる。未解析の追加部分もescaped textで保持し、全文表示ボタンや切り捨てで代用しない。
- Worker化はfallbackだけでテストを通さない。本番Viteのinline WorkerでもDOM依存がなく動くこと、
  重い解析中に実入力とUI heartbeatが処理されることを描画検査する。単なる解析の所要時間と入力遅延を混同しない。
- 出力DOMの削減では同じスタイルの連続テキストをまとめ、全文・改行・色の境界・選択／コピーを維持する。
  8行previewの高さ制限だけでDOM件数も減るとは扱わない。
- `transcript-ui.test.ts` は、1000モデルの新規Composerで入力中のcatalog再走査が0回、
  IPC更新で変更のないツールの再描画が0回、変更されたツールだけ更新されることも検査する。

## 8. 変更時の確認チェックリスト

- [ ] 新しい通常Cardが不透明になっていない。文字・アイコンのopacityも変えていない。
- [ ] 同じ役割の枠の左右端と、アイコン列の上下余白が揃っている。
- [ ] 縦・横・両方のスクロールで、始端と終端の余白が同程度。
- [ ] 最下端・最右端でも、親の角丸でthumbが見切れない。
- [ ] 短い内容では不要なスクロールがなく、長い内容は最後まで読める。
- [ ] 通常幅・狭い幅・文字サイズ変更で、約8行の出力枠と整列を維持する。
- [ ] hover / focus / 展開 / 折り畳み / 状態変化で、透過感と周囲の配置を壊していない。
- [ ] 指摘された1箇所だけでなく、同じ共通実装を使う表示も確認した。

CSSの数値やDOMだけで完了扱いにせず、実描画も確認する。
`apps/desktop/src/mainview/transcript-ui.test.ts` には、Edgeのスクリーンショットから
スクロールバーの端の余白・見切れを確認する回帰テストと、文字サイズを変えた8行上限の検証がある。
スクロール・出力枠の変更時はこれを維持・拡張する。Cardの背景alpha・全体opacityも自動検査するが、
実際の背景との見え方など、未検証の見た目は実画面でも確認し、確認できなかった点は明記する。
`test:ui` はEdge/Chromiumがなければ失敗する。標準のEdge以外を使う場合は
`PIG_UI_BROWSER` に実行ファイルのパスを指定する。

```powershell
mise exec -- pnpm typecheck
mise exec -- pnpm lint
mise exec -- pnpm test:ui
```
